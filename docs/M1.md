## Crate design (codebase-design vocabulary)

- `core` — pure domain logic later. M1: empty placeholder, no deps.
- `db` — ALL welds types live here. Interface = `Db` (connection factory + migrate), `Auth` service struct, models. Implementation = welds models + raw SQL (upsert). External seam: `db::Auth::{is_authorized, authorize, revoke, list_authorized, is_admin}`.
- `bot` — ferogram handlers only. Reads env, builds client + dispatcher, delegates all persistence to `db::Auth`. Handlers capture `Arc<BotState>` (client + auth service).

`Auth` interface (Rust, `crates/db/src/auth.rs`):
```rust
pub struct Auth { /* client: welds Client (cheap clone), admin_id: i64 */ }
impl Auth {
    pub fn new(client: welds::connections::PostgresClient, admin_id: i64) -> Self;
    pub fn is_admin(&self, user_id: i64) -> bool;                    // pure
    pub async fn is_authorized(&self, user_id: i64, chat_id: Option<i64>) -> Result<bool, DbError>;
    pub async fn authorize(&self, telegram_id: i64, name: Option<&str>) -> Result<bool /*newly_added*/, DbError>;
    pub async fn revoke(&self, telegram_id: i64) -> Result<bool /*revoked*/, DbError>;
    pub async fn list_authorized(&self) -> Result<Vec<AuthedPeer>, DbError>; // telegram_id, name, created_at (chrono DateTime<Utc>), ordered by created_at
}
```
`is_authorized` parity: admin always true; else true if user_id OR chat_id (when Some and != user_id) exists in users. `authorize` parity: upsert (insert on conflict update name), `newly_added` = didn't exist before. `revoke`: delete, `revoked` = row existed.

## DDL (crates/db/src/migrations.rs)

Single welds `Manual` migration `initial_schema`, exact drizzle DDL: `users`, `tracks`, `requests`, `settings` tables (from `drizzle/0000`), `pg_trgm` extension + all indexes incl. `tracks_search_trgm_idx` gin expression index (from `drizzle/0001`), `settings` is in 0000 batch — use final combined DDL of all three files minus `--> statement-breakpoint` markers. Run via:
```rust
use welds::migrations::{Manual, MigrationStep, up};
fn initial_schema(_s: &TableState) -> Result<MigrationStep> {
    Ok(MigrationStep::new("initial_schema", Manual::up(SQL).down("DROP TABLE users, tracks, requests, settings CASCADE; DROP EXTENSION IF EXISTS pg_trgm;")))
}
```
`up(client.as_ref(), &[initial_schema])` on boot. Types: `timestamp with time zone` → `DateTime<Utc>`; bigint PK `telegram_id` (i64, no auto-increment); serial PKs.

welds model for `users` (only table M1 needs; do NOT model tracks/requests/settings yet — add when their features arrive):
```rust
#[derive(Debug, Clone, WeldsModel)]
#[welds(schema = "public", table = "users")]
pub struct User { #[welds(primary_key)] pub telegram_id: i64, pub name: Option<String>, pub created_at: DateTime<Utc> }
```
Upsert via welds raw SQL through the `Client` trait (`execute`): `INSERT INTO users (telegram_id, name) VALUES ($1, $2) ON CONFLICT (telegram_id) DO UPDATE SET name = EXCLUDED.name` — pre-check existence for `newly_added` in same pattern as TS (select then upsert).

## Bot crate (crates/bot/src/)

`main.rs` sequence (mirrors TS main.ts):
1. `dotenvy::from_filename(".env")` (ignore missing; worktree has .env) + env vars; require `API_ID` (i32), `API_HASH`, `BOT_TOKEN`, `ADMIN_ID` (i64), `DUMP_CHANNEL_ID` (i64 parse of `-100...`), `DATABASE_URL`, `LOG_LEVEL` (tracing EnvFilter: default `info`; map `critical`→`error`). Missing/invalid => panic with clear message listing the bad vars (parity: env.ts throws).
2. `tracing_subscriber` init.
3. DB connect (welds postgres connect), migrations up. Log info lines mirroring TS: "Running database migrations...", "Migrations completed successfully!".
4. ferogram client:
```rust
let (client, shutdown) = ferogram::Client::builder()
    .api_id(env.API_ID).api_hash(&env.API_HASH)
    .session("bot-data/session")     // file session, persists across restarts
    .catch_up(true)
    .connect().await?;
client.bot_sign_in(&env.BOT_TOKEN).await?;
client.save_session().await?;         // persist auth session
let me = client.get_me().await?;
info!("Bot started successfully" username=..., bot_id=..., dump_channel=...);
```
5. Dispatcher (`ferogram::filters::Dispatcher::new()`), register: start, help, auth, revoke+unauth (two separate `on_message` registrations — ferogram `command()` takes ONE name, match-all semantics are fine since names are distinct), authlist, one `on_callback_query` handling `authpage:`/`authclose`/`noop` (filter: `custom` on `q.data()`). Spawn per-update (`tokio::spawn`) with `Arc<Dispatcher>`, match-all semantics noted.
6. SIGINT/SIGTERM => `shutdown.cancel()`; log "Shutting down bot...".

Handler parity (closure captures `Arc<BotState> { client: ferogram::Client, auth: db::Auth }`):

- **start**: reply exactly `Hello, world!` (plain text — TS uses `filters.start` + answerText plain).
- **help**: `auth.is_authorized(sender, chat)`, if false return silently (no reply). Then VERBATIM help.ts text incl. admin section when `is_admin`. HTML via `InputMessage::html(...)`. Note: ferogram html feature = entity parsing. TS `parseDynamicHtml` converts `<br/>` to newlines and `<blockquote>`/`<blockquote expandable>` to custom emoji entities — check `/home/hitarashi/sayeed/github/alac-bot/src/utils/html.ts` and replicate its transform: convert the HTML string to Telegram entities. If ferogram's `InputMessage::html` handles `<b>/<i>/<code>/<a>` but NOT `<br/>` or `<blockquote>`, port the TS transform into a `bot::html` helper that rewrites those tags before passing to ferogram.
- **auth** (admin only, silent return for non-admins): resolve target:
  1. replied-to message sender: use `msg.reply_to_message_id()` + `client.get_messages(chat_peer, &[id])` — sender id from returned message (`sender_id()` peer → user id; name: first/last or username or `User {id}`). NOTE: `getReplyTo` in TS returns the reply message sender; if no reply-to msg or fetch fails → fall through.
  2. else first arg: if parses as i64 → that id, `isUser = id > 0`, name `User {id}`; if starts with `@` → `client.resolve(PeerRef::Username)` → id + name; else null.
  3. else if chat not private → authorize the chat itself.
  4. else null → usage message (verbatim auth.ts).
  Then `getPeerLink` parity (username → t.me link else tg://user?id= or t.me/c/ links; name from resolve when available), `authorize()`, reply `✅ <b>{Authorized|Updated} {User|Group}:</b> {icon} <a ...>{name}</a> (<code>{id}</code>)` — escape name!
- **revoke** (aliases revoke, unauth): same shape as auth, replies verbatim from revoke.ts.
- **authlist**: admin only silent otherwise; page arg parse parity (NaN/<1 → 1); render list per renderAuthListPage: PAGE_SIZE 20, clamp page, numbered rows `N. {icon} <a href>{name}</a> — <code>{id}</code>` in blockquote, `Page X/Y • Total: N` footer when >1 page, inline keyboard: nav row `< Prev` / `X / Y` (noop) / `Next >` + row `Refresh` / `Close`. Empty list message verbatim. Pagination callbacks: `authpage:N` re-render via edit, `authclose` delete message, `noop` just answer. Edit via `client.edit_message(peer, id, InputMessage::html(text).reply_markup(kb))`; swallow `NOT_MODIFIED`-style edit errors.
- **Unauthorized callback**: `q.answer().alert(true).text("Unauthorized.").send(&client)`.

Message send: `msg.reply(InputMessage::html(html_str))` for replies; `client.send_message(PeerRef::Id(chat_id), ...)` for edit-paging targets. For `reply_markup`: `InlineKeyboard::new().row([...Button::callback("Refresh", b"authpage:1")...]).into_markup()` passed via `InputMessage` builder (check `input_message.rs` for `reply_markup` method).
