### Mirror policy (`mirror-policy.ts`)

- Env override path: if BOTH mirror URL and API key are configured → strip trailing `/+` from URL, return immediately. No circuit/cache interaction. Engine stays env-pure: constructor takes `env_override: Option<(String, String)>` (bot passes env values later; engine never reads process env).
- Constructor params (all overridable for tests): `failure_cooldown = 30s`, `cache_ttl = 1h`, `health_timeout = 8s`.
- Circuit breaker: `is_circuit_open()` = last_failure exists AND elapsed < cooldown. `record_failure(msg)` stores `{time, error}`. `record_success()` clears it.
- `get_endpoint(force_refresh: bool, signal: Option<CancellationToken>)` flow:
  1. env override → return (no state touched)
  2. `!force_refresh && circuit_open && last_failure` → throw the STORED error string (no new record)
  3. `!force_refresh && cached && expires_at > now` → return cached (no re-verify)
  4. Fetch manifest URL (hardcode the decoded constant; TS stores b64 `aHR0cHM6Ly9naXN0LmdpdGh1YnVzZXJjb250ZW50LmNvbS9NYW5PZkluZmluaXR5L2VjNmRiNzlmMDMxZDU4NjQwYzg0YjIyNWM0Yzc4Y2FiL3Jhdw==`, decoded = `https://gist.githubusercontent.com/ManOfInfinity/ec6db79f031d58640c84b225c4c78cab/raw`) with Chrome UA `Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/145.0.0.0`, health_timeout.
     - ANY adapter failure (timeout/cancel/network) → `record_failure` + throw `Mirror manifest lookup timed out after {elapsed_ms}ms: {adapter_msg}`
     - HTTP !ok → `record_failure` + throw `Failed to fetch mirror manifest (HTTP {status})`
  5. Parse JSON `{source?: {apple?: string}, mirrors?: {apple?: string}, key?: string, api_key?: string}`. **PARSE ERRORS PROPAGATE RAW AND DO NOT RECORD FAILURE** (TS `resp.json()` is outside try/catch) — `MirrorError::Json(serde_json::Error)` variant.
     - mirror = `(source.apple || mirrors.apple || "")` trailing-slash-stripped; api_key = `(key || api_key || "").trim()`
     - missing either → `record_failure` + throw `Mirror manifest returned empty apple endpoint or api key`
  6. GET `{mirror}/status` with Chrome UA + `X-API-Key: {api_key}`, health_timeout.
     - adapter failure → `record_failure` + throw `Mirror /status check timed out after {elapsed_ms}ms: {adapter_msg}`
     - !ok → `record_failure` + throw `Mirror /status check failed (HTTP {status})`
  7. Parse /status JSON with **catch → `{}`** (parse failure = empty object, NOT an error): `{wrapper_lossless_available?: bool, wrapper_instances?: array}`.
     - Offline iff `wrapper_lossless_available === false` OR (`wrapper_instances` is an array AND empty) → `record_failure` + throw `Lossless wrapper is currently offline on mirror`
     - (undefined fields / non-array instances → NOT offline)
  8. Success: cache `{mirror_url, api_key, expires_at: now + cache_ttl}`, `record_success()`, return.
- Use `std::time::Instant` for circuit/cache timing (constructor-parameterized for tests). Locking: `std::sync::Mutex<PolicyState>` held only for short sync reads/writes, NEVER across `.await` (TS is single-threaded; races allowed, parity fine).
- `clear_cache()` clears cached + last_failure.

### HTTP seams (`http.rs`)

Two small traits (RPITIT, static dispatch like M2's catalog transport):

```rust
/// Text-body GET for the mirror policy (manifest + /status).
pub trait MirrorHttp: Send + Sync {
    fn get(&self, url: &str, headers: &[(&str, String)], timeout: Duration, signal: Option<&CancellationToken>)
        -> impl Future<Output = Result<String, MirrorHttpError>> + Send;
}
pub enum MirrorHttpError { Timeout { elapsed_ms: u64 }, Cancelled, Status(u16), Network(String) }

/// Streaming GET for the audio endpoints (handshake = headers arrival).
pub trait StreamHttp: Send + Sync {
    fn fetch(&self, url: &str, api_key: Option<&str>, handshake_timeout: Duration, signal: Option<&CancellationToken>)
        -> impl Future<Output = Result<StreamHttpResponse, StreamHttpError>> + Send;
}
pub struct StreamHttpResponse {
    pub status: u16,
    pub codec: Option<String>,      // x-codec
    pub bit_depth: Option<String>,  // x-bitdepth
    pub sample_rate: Option<String>, // x-samplerate
    pub body: Option<ByteStream>,   // None == TS `!resp.body`
}
pub type ByteStream = Pin<Box<dyn Stream<Item = Result<Bytes, StreamBodyError>> + Send>>;
pub enum StreamBodyError { Network(String) }
pub enum StreamHttpError { Timeout { elapsed_ms: u64 }, Cancelled, Network(String) }
```

`ReqwestHttp` implements both (Clone, holds a `reqwest::Client`):
- Text GET: send with timeout(reqwest per-request timeout covers the text read — fine for small bodies), `.error_for_status`-style manual !ok → Status, is_timeout → Timeout with elapsed, else Network(err.to_string()).
- Stream GET: **timeout must cover the HANDSHAKE ONLY** — wrap `send()` in `tokio::time::timeout` (reqwest's `.timeout()` would kill long bodies). Then read status + the three headers, body = `resp.bytes_stream()` mapped to `StreamBodyError::Network`. On !ok still return the response (status + body) so the caller can build the error message from the body — see below.
- Cancellation: select on `signal.cancelled()` where present.

### Stream transport (`stream-transport.ts`)

- `StreamTransport::new(default_timeout = 15s)` (constructor param).
- `fetch_endpoint(options)`:
  - Already-cancelled signal → Err `Download was cancelled`
  - Handshake through the adapter; map errors:
    - `Timeout` → Err `Stream handshake timed out after {timeout_ms / 1000}s on {source_name}` (integer seconds)
    - `Cancelled` → Err `Download was cancelled`
    - `Network(msg)` → Err with raw msg
  - `!status.is_success()` → drain body as text (adapter helper or collect stream; errors → `''`), Err `HTTP {status} on {source_name}: {text first 120 chars}`
  - `body == None` → Err `Empty body returned from {source_name}`
  - Map headers: codec = `x-codec` or `alac`; bit_depth = parse or 24; sample_rate = parse or 96000. (TS `parseInt` on garbage yields NaN — we use the default instead; acceptable deviation on malformed mirrors only, note in code comment.)
  - UA is set by the adapter (Chrome UA); `X-API-Key` only when api_key present.
- `AudioStreamSource { stream: ByteStream, source_name: String, codec: String, bit_depth: u32, sample_rate: u32 }`
- `connect_audio_stream(options: ConnectStreamOptions) -> Result<AudioStreamSource, StreamError>`:
  - Options: `track_id, primary_mirror: Option<MirrorEndpoint>, wrapper_url: Option<String>, wrapper_api_key: Option<String>, signal: Option<CancellationToken>, on_progress: Option<Arc<dyn Fn(&str) + Send + Sync>>, mirror_policy: Option<&dyn MirrorPolicy>`
  - Policy defaults: TS uses the global manager — for engine purity, `connect_audio_stream` takes `&dyn MirrorPolicy` (bot passes its instance; for unit tests a fake). (`MirrorPolicy` trait: `record_success(&self)`, `record_failure(&self, &str)` — the policy manager implements it.)
  - 1. Primary mirror (if given): URL `{mirror_url trailing-slashes-stripped}/api/stream/{track_id}`, source name `primary mirror ({hostname})` — hostname extracted like `new URL(url).hostname` (write a tiny parser: after `://` up to first of `/:?`, strip port — NO url crate). Success → `policy.record_success()`, return. Failure → push `Primary mirror failed: {msg}`; `if !signal.aborted { policy.record_failure(msg) }` (check the token: `is_cancelled()`).
  - 2. No wrapper URL (trimmed, trailing-slashes-stripped — note: empty after trim counts as none) → Err `Audio streaming failed and no wrapper URL is configured. Errors: {errors joined by '; '}`
  - 3. `on_progress("Primary mirror unavailable. Connecting to fallback wrapper...")` (exact string; fires exactly once)
  - 4. Wrapper candidates in order: `{wrapper}/api/stream/{track_id}`, `{wrapper}/stream/{track_id}`, source name `wrapper ({clean_wrapper})`, api key = wrapper_api_key. Per-candidate: pre-check `signal cancelled` → Err `Download was cancelled` (caught → aggregated). Failure → push `Wrapper candidate ({candidate_url}) failed: {msg}`.
  - 5. All failed → Err `Failed to stream audio from all sources. All streaming endpoints failed for track {track_id}. Errors: {errors joined by '; '}`
- `StreamError`: `Message(String)` (all the above texts) — message IS the interface (surfaces to users later).

### Queue (`queue.ts`)

`SequentialRipQueue` — sequential task runner with abort + position callbacks:

```rust
pub struct EnqueueOptions {
    pub on_position_change: Option<Arc<dyn Fn(u64) + Send + Sync>>,
    pub on_start: Option<Arc<dyn Fn() + Send + Sync>>,
    pub signal: Option<CancellationToken>, // outer cancellation
}
pub enum QueueError { Aborted, Cleared }  // Display: "Job was aborted", "Queue cleared"
impl SequentialRipQueue {
    pub fn new() -> Self;
    pub async fn enqueue<T: Send + 'static>(
        &self,
        task: impl FnOnce(CancellationToken) -> Pin<Box<dyn Future<Output = T> + Send>> + Send + 'static,
        options: Option<EnqueueOptions>,
    ) -> Result<T, QueueError>;
    pub fn get_pending_count(&self) -> usize;
    pub fn is_processing(&self) -> bool;
    pub fn clear(&self); // aborts + fails all PENDING items; active item untouched
}
```

TS parity behaviors (verified from queue.ts):
- Pre-aborted outer signal at enqueue → immediate `Err(Aborted)`, nothing queued.
- Item gets its own child `CancellationToken` (TS controller); the task closure receives it.
- First enqueue into an idle queue starts immediately — **no position callback for it**. Enqueue while processing → `on_position_change(queue_len_after_push)` (1-indexed).
- On dequeue: remaining items get `on_position_change(i+1)`. `on_start` fires when the item begins.
- Outer signal fires while PENDING: remove from queue, notify items from that index onward with `i+1`, cancel the child token, enqueue's await resolves `Err(Aborted)`.
- Outer signal fires while ACTIVE: cancel the child token only — the task observes cancellation and its own result/error propagates to the awaiter (TS rejects with the TASK's error, not 'Job was aborted').
- `clear()`: all pending → child cancelled + `Err(Cleared)`; queue emptied; active item unaffected.
- Worker: single runner task spawned (or Notify-driven loop) when an item is enqueued into an idle queue; `is_processing()` true while any item runs (keep the flag set across the whole loop for consistent observation).

One workable internal design (adjust if cleaner): enqueue wraps the user task into a uniform `FnOnce(CancellationToken) -> Pin<Box<dyn Future<Output = Result<Box<dyn Any + Send>, QueueError>> + Send>>` plus a type-erased `complete: Box<dyn FnOnce(Result<Box<dyn Any + Send>, QueueError>) + Send>` that downcasts and sends through a `oneshot::channel<Result<T, QueueError>>`. Items hold task + complete + child token + callbacks + outer signal + a per-item `Arc<Notify>` to stop the abort-watcher when dequeued normally. Pending-abort is handled by a spawned watcher (`select!` on outer signal vs the Notify); active-abort is handled inside the runner (`select!` on outer signal → cancel child → then await task completion so the task's own payload completes the channel). Panics in tasks must not stall the queue or hang the awaiter: catch (`AssertUnwindSafe(fut).catch_unwind()`) → complete with `Err(Task panic message)` — add `QueueError::Task(String)` hidden from docs as edge case. Invoke user callbacks AFTER releasing the queue mutex (collect notifications, then fire) to avoid deadlock if a callback spawns/talks Telegram.
